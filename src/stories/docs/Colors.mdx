# Colors & Theme Overrides

`@royal-duck/serving-duck` features a **3-tier semantic token architecture** built around CSS custom properties (`--sd-*`) and mapped directly into **Tailwind CSS v4** via `@theme inline`.

---

## 1. Token Architecture

The design system separates color definitions into three distinct tiers:

1. **Primitive Colors**: Raw hex values (e.g., `#6366f1` Indigo, `#fbbf24` Gold, `#020617` Deep Slate).
2. **Semantic CSS Custom Properties**: Context-aware variables defined in `tokens.css` (e.g., `--sd-primary`, `--sd-bg-canvas`, `--sd-fg-primary`).
3. **Tailwind CSS v4 Utilities**: Inline `@theme` mappings in `theme.css` (e.g., `bg-sd-primary`, `text-sd-fg`, `bg-sd-canvas`, `border-sd-border`).

```
┌─────────────────────────────────┐
│       Consuming Application     │
│   (Optionally overrides --sd-*) │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│     Semantic CSS Variables      │
│  (--sd-primary, --sd-bg-canvas) │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│    Tailwind CSS v4 Utilities    │
│  (bg-sd-primary, text-sd-fg)    │
└─────────────────────────────────┘
```

Because Tailwind v4 utilities point directly to CSS variables, **any runtime or build-time override of `--sd-*` variables instantly ripples through all Tailwind classes and components** without requiring CSS recompilation!

## 4. How Color Overrides Work

Because all styling relies on CSS variables, you have full freedom to customize colors at any level of specificity.

### A. Global Application Theme Override

To skin the entire design system to match your organization's brand, re-declare the `--sd-*` variables on `:root` in your app's global stylesheet:

```css
/* In your app's main CSS (after importing theme.css or style.css) */
:root {
  /* Change brand primary to Cyan */
  --sd-primary: #06b6d4;
  --sd-primary-hover: #22d3ee;
  --sd-primary-fg: #082f49;

  /* Change brand accent to Rose */
  --sd-accent: #f43f5e;
  --sd-accent-hover: #fb7185;
  --sd-accent-fg: #ffffff;

  /* Customize focus ring */
  --sd-ring-focus: #06b6d4;
}
```

### B. Theme Switching (Dark vs Light Mode)

The system defaults to **Dark Mode** out of the box on `:root`.

To activate **Light Mode**, set `data-theme="light"` or add the `.light` class to your `<html>`, `<body>`, or any subtree container:

```html
<!-- Whole application in light mode -->
<html lang="en" data-theme="light">
  <body>
    ...
  </body>
</html>

<!-- Or on any container/card -->
<div data-theme="light" class="bg-sd-surface p-6 rounded-sd-md border border-sd-border">
  <SDTitle as="h2" title="Light Subtree" />
</div>
```

To explicitly force **Dark Mode** on a subtree within a light-themed page:

```html
<section data-theme="dark" class="bg-sd-canvas text-sd-fg p-8">
  <SDTitle as="h2" status="primary" title="Dark Cockpit View" />
</section>
```

### C. Scoped Subtree Overrides

You can create distinct color contexts for specific sections of your application (for example, a game HUD, a terminal modal, or a billing banner) by declaring CSS variables under a custom CSS class:

```css
/* Custom Gaming Cockpit / HUD */
.hud-cockpit {
  --sd-bg-canvas: #09090b;
  --sd-bg-surface: #18181b;
  --sd-border-default: #00f0ff;
  --sd-primary: #00f0ff;
  --sd-primary-hover: #38bdf8;
  --sd-primary-fg: #09090b;
  --sd-accent: #ff007f;
}
```

```html
<div class="hud-cockpit bg-sd-surface border border-sd-border p-6 rounded-sd-lg">
  <SDTitle as="h3" status="primary" title="Ship Diagnostics" />
  <!-- All child Serving Duck components will automatically inherit the HUD colors -->
</div>
```

### D. Inline Component-Level Overrides

For quick one-off tweaks, pass style overrides directly to component instances:

```html
<SDTitle
  as="h2"
  title="Special Event"
  style="--sd-fg-heading: #ec4899;"
/>
```

### E. Forced Colors & Accessibility Mode

`tokens.css` contains built-in `@media (forced-colors: active)` rules that automatically translate `--sd-*` tokens to system keywords (`Canvas`, `CanvasText`, `ButtonText`, `Highlight`, `Mark`):

- High-contrast mode users on Windows and assistive devices receive full contrast without any custom CSS.
- Status dots on `SDTitle` automatically render a 1px border in forced-colors mode to remain clearly visible.
